### 2. Clues from python's introspection system

`marshal.loads(sequencer_code)` returns a code object passed to `exec`. `marshal` is a fast internal serialization format that supports basic built-in types and code objects.
Code objects are compiled bytecode—the executable representation of python code used by the interpreter.
Higher-level objects such as functions, lambdas, classes, and modules built on code objects and wrap them with additional runtime context and metadata.

Code objects expose a set of attributes produced during compilation and used by the interpreter. You can find a list of said attributes [here](https://docs.python.org/3/reference/datamodel.html#code-objects). The one we care about is co_code, which stores the VM bytecode itself.
Though, we won't interact with it directly, we'll let the disassembler from `dis` do the heavy lifting for us.

#### 2.1 Decompiling the sequencer

For the first part I'll use a decomiler. [pycdc](https://github.com/zrax/pycdc.git) should work fine with python3.12 so we'll go with that. `pycdc` takes a `.pyc` file as input, so we need to create one from our code object. We'll use [this](https://stackoverflow.com/questions/73439775/how-to-convert-marshall-code-object-to-pyc-file/73454818#73454818) method.

```py
import zlib
import marshal
import importlib

encrypted_sequencer_data = b'x\x9cm\x96K\xcf\xe2\xe6\x15\xc7\xfd\ ...'
sequencer_code = zlib.decompress(encrypted_sequencer_data)
code_object = marshal.loads(sequencer_code)


def pyc_from_co(co):
    data = importlib._bootstrap_external._code_to_timestamp_pyc(co)

    with open('sequencer.pyc', 'wb') as f:
        f.write(data)


def main():
    pyc_from_co(code_object)


if __name__ == "__main__":
    main()
```

Running the decompiler against the generated `.pyc` file gives us the following decompilation:

We can get the `encoded_catalyst_strand` directly from the `sequencer_code_object`, through the co_consts attribute.


Now all that's left is the generator_function itself, it loads the iterator (`.0`) from the top of the stack, then `FOR_ITER` essentially does

So the simplified python source ends up looking like...

```py
user_signature = bytes(c ^ (i + 42) for i, c in enumerate(current_user))
```
